A guide to your coding workspace and workflow for the semester.

Initial One-Time Setup

Before you can begin working, you need to complete a few one-time setup steps. Please follow these in order.

  1. Create a GitHub Account: If you do not already have one, go to github.com/join to create a free account.
  2. Join our GitHub Classroom: Click the link below and accept the "Setup" assignment to be added to our course organization.

    Classroom Setup Link: https://classroom.github.com/a/y4-MAF99

  3. Create your "Home" Repository: Navigate to the Home repository template link below. Click "Use this template" -> "Create a new repository". Ensure the "Owner" is 1436-TCCD-MTN and name the repository firstname_lastname.

    Home Repository Template Link: https://github.com/1436-TCCD-MTN/Home

  4. Set up your "Home" Codespace: From your newly created personal Home repository, create your codespace. This will be your primary development environment.
  5. Install Tools: Your Codespace needs a few tools installed. Run the following commands one by one in the terminal:

    # Install the Rust toolchain (choose option 1)

    curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

    # Install git-cliff for changelogs

    cargo install git-cliff
  6. Set Up Pre-Commit Hooks: Our projects use automated checks to ensure code quality before you commit. In each assignment and project repository you clone, you will need to run this one-time setup command from inside that project's folder:
    git config core.hooksPath .githooks

The Professional Git Workflow

We will use the command-line Git workflow that is standard in the software development industry. This process ensures that your work is saved incrementally and that collaboration is smooth and organized.

Individual Assignment Workflow

For your weekly homework, you will follow this cycle:

  1. Clone & Setup: In your "Home" Codespace terminal, use git clone to download the assignment repository. cd into the new folder and run git config core.hooksPath .githooks once.
  2. Create a Branch: Before writing any code, create a new branch for your work. For example: git checkout -b feat/implement-game-logic
  3. Write Your Code: Work on the assignment, saving your files as you go.
  4. Commit Your Work: Save your progress in small, logical chunks. The pre-commit hooks will automatically check your formatting and commit message. The cycle is:
    • git add - Stage the specific file you changed.
    • git commit - Open the editor to write a detailed semantic commit message.
  5. Push Your Branch: Back up your work to GitHub: `git push --set-upstream origin feat/implement-game-logic`
  6. Generate Changelog: Before creating your PR, update the changelog file:
    • git cliff -o CHANGELOG.md - Generate the changelog.
    • git add CHANGELOG.md - Stage the updated file.
    • git commit -m "chore: update changelog" - Commit the changelog.
    • git push - Push the final commit.
  7. Create a Pull Request: On GitHub, create a "Pull Request" to merge your branch into the main branch.

Group Project Workflow

The group project follows the same basic workflow but adds a crucial collaboration step: Peer Code Review.

  1. Claim an Issue & Create a Branch.
  2. Write Code & Commit Iteratively.
  3. Generate Changelog & Push Final Changes.
  4. Create a Pull Request: Formally propose your changes.
  5. Request a Review: In your Pull Request, you will request a review from at least one other member of your project group.
  6. Peer Code Review: Your teammate will review your code, leave comments or questions, and ultimately "Approve" your changes.
  7. Merge: Only after your Pull Request has been approved by a teammate can it be merged into the main branch.
